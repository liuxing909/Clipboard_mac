# 性能测量与边界

这里保留历史基准及测量条件，用于理解优化方向。它们不是当前版本完整 GUI 的性能承诺，也不是应用的内存硬上限。调度和资源控制的实现见 [架构说明](ARCHITECTURE.md)。

## 复现入口

在仓库根目录执行：

```sh
bash scripts/build.sh --native
.build/release/ClipboardDeck --benchmark
.build/release/ClipboardDeck --benchmark-office
.build/release/ClipboardDeck --benchmark-thumbnails
```

命令输出 JSON，使用临时目录、合成素材，以及测试所需的命名剪贴板和隔离设置；不访问系统通用剪贴板、不注册全局快捷键、不打开真实 Office 窗口。临时记录和设置会在结束后清理。

新增记录应注明版本、硬件、系统、构建模式和采样条件，避免与编译或其他基准同时运行。不同版本的计时范围可能变化，比较前应检查原始 JSON 的字段和说明。

## 列表与后台监听

2026-11-03，在 Apple M5 / 16 GB / macOS 26.3.2 上，以 release 构建顺序运行同一基准一次。基线为冻结的 0.1.1 实现加同一基准入口，优化版本为 0.1.2。

| 模拟项目 | 0.1.1 | 0.1.2 |
| --- | ---: | ---: |
| 200 条记录，1,000 次列表导航合计 | 152.23 ms | 17.12 ms |
| 100 个不同搜索词合计 | 132.66 ms | 134.28 ms |
| 监听空闲 10 秒，平均 CPU | 0.028% | 0.029% |
| 暂停空闲 5 秒，平均 CPU | 0.021% | 0.004% |
| 监听空闲阶段物理内存 | 7.83 MiB | 7.61 MiB |
| 生成、保存并加载 20 张图片合计 | 167.62 ms | 166.15 ms |
| 图片阶段结束后物理内存 | 10.86 MiB | 10.25 MiB |

每条模拟文字为 256 字符，图片为 600 × 600 像素。两版均读取 200,000 个导航列表项、得到 100 个搜索匹配并加载 20 张缩略图。CPU 的 100% 表示占满一个核心，物理内存使用 `task_vm_info.phys_footprint`。

重复导航计算明显减少，搜索和正常监听的本次测量基本相同。短时单次采样的微小差异存在波动，不能保证日常占用。测试加载 AppKit 运行时但没有真实窗口；图片阶段还包含素材生成和存储，不能当作 GUI 打开速度或单独解码速度。

原始数据：[0.1.1 基线](../Benchmarks/baseline-0.1.1.json)、[0.1.2 优化后](../Benchmarks/optimized-0.1.2.json)。

[0.1.4 记录](../Benchmarks/runtime-0.1.4.json) 的图片阶段加入后台排队和主运行循环等待，耗时定义已变化，不能直接计算相对旧版的加速比例。[0.1.5 记录](../Benchmarks/runtime-0.1.5.json) 中，模型监听空闲约 0.035% 单核 CPU、4.42 MiB 物理内存，暂停约 0.003% 单核 CPU；仍为无窗口、短时单次探测，主要用于检查后台任务没有形成忙循环。

## 办公内容处理

2026-11-03，在相同机器上使用 0.1.5 release 构建，每个场景预置 200 条短文字历史，运行 3 次，列出三次中的最大观测值：

| 合成内容 | 采集主线程调用 | 完整入库 | 准备并回写 | 物理内存采样峰值 |
| --- | ---: | ---: | ---: | ---: |
| RTF + HTML 段落 | 0.211 ms | 5.59 ms | 5.66 ms | 6.31 MiB |
| RTFD 内嵌小图片 | 0.050 ms | 5.55 ms | 5.63 ms | 6.19 MiB |
| 300 万像素 JPEG | 0.145 ms | 77.39 ms | 22.91 ms | 23.39 MiB |

计时包含约 5 ms 的完成检测间隔。主线程调用只包含快照采集，完整入库另含后台处理和同步写盘。内存每 5 ms 采样，可能遗漏短暂峰值，且包含合成素材和运行时；没有真实应用窗口，不能视为 Word / WPS 兼容性或整个 GUI 内存上限。

原始数据：[办公内容基准](../Benchmarks/office-0.1.5.json)。

## 缩略图缓存

0.1.6 将列表缩略图改为按 728 × 244 像素框等比例适配，预览保持最长边 600 像素。列表与预览使用不同缓存标识，共享 12 MiB / 32 项预算和单并发队列。

2026-11-03，同一组合成 PNG，每种策略预热一次后交替测量 5 次：

| 图片比例 | 原缩略图像素成本 | 列表缩略图像素成本 | 降幅 | 单次解码中位耗时（原 → 新） |
| --- | ---: | ---: | ---: | ---: |
| 方图 | 1406.2 KiB | 232.6 KiB | 83.5% | 7.62 → 9.02 ms |
| 竖图 | 703.1 KiB | 118.2 KiB | 83.2% | 5.55 → 6.69 ms |
| 横图 | 703.1 KiB | 465.1 KiB | 33.8% | 6.26 → 7.55 ms |

在相同缓存预算下模拟 20 个独立键顺序浏览两遍：第二遍旧策略命中 0/20、重新解码 20 次，新策略命中 20/20、重新解码 0 次；耗时约 154.33 ms → 0.0036 ms。

**本组 PNG 单次解码略慢，收益主要是较小的像素缓冲和较高的缓存命中率。** 成本只计解码输出的 `bytesPerRow × height`，不是进程内存。重复浏览使用同一合成图片配 20 个不同键，不是 20 张真实照片，也不包含真实滚动、队列等待或 UI。浏览顺序和图片比例会改变结果；超宽图的列表输出可能大于旧策略，预览仍使用原有 600 像素策略。

原始数据及完整限制：[缩略图比较基准](../Benchmarks/thumbnails-0.1.6.json)。

## 当前资源预算

- 缩略图缓存最多 12 MiB / 32 项，按解码像素成本记账；缩略图队列最多 8 个未完成请求。
- 格式解析、图片转换与粘贴准备共用单并发队列，最多 2 个未结束任务，输入计费最多 50 MiB；单次快照和准备输出各限 25 MiB。
- 已取消但仍在执行的工作继续占用预算；内存压力升高时释放缓存与展示引用，并暂停新加载。

这些限额约束应用管理的任务和缓存，**不是整个进程的内存上限**。系统剪贴板 IPC、来源应用按需生成数据、临时解码分配、显示中的图片对象及 AppKit 运行时仍会占用资源。系统剪贴板读取、最终写回和历史写盘仍同步执行。
